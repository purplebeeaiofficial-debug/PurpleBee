기여 기반 구독은 이렇게 동작합니다

사용자가 예약한 시간 동안 유휴 자원을 안전하게 제공하면, Purple Bee는 그 기여 시간을 계정에 반영하고 기준을 만족했을 때 Basic, Plus, Pro 등급에 맞는 혜택을 활성화합니다.

1. 시간 예약 사용자가 기여 가능한 시간을 직접 선택합니다. 예약 전에는 현재 기기 상태와 사용량 제한 설정을 다시 확인합니다.
2. 안전한 기여 실행 기여 클라이언트는 CPU·GPU 상한, 사용자 활동 여부, 네트워크 상태를 확인하며 작은 작업 단위만 처리합니다.
3. 점수 환산 기여 시간은 하드웨어 등급, 성공률, 실제 처리량을 반영해 유효 기여 시간으로 계산됩니다.
4. 구독 활성화 유효 기여 시간이 기준을 넘으면 상위 플랜 혜택이 즉시 활성화되거나 기존 만료일 뒤로 연장됩니다.
100대의 기여 노드가 300명의 요청을 보조할 때도 가중치를 조정합니다

기본적으로 모든 사용자는 자신의 기기에서 먼저 실행을 시작합니다. 상위 플랜은 여기에 분산 기여 노드의 보조 연산을 추가로 배정받고, 중앙 조정 서버는 노드 상태, 기여 예약, 실패율, 작업 유형, 재시도 횟수를 기준으로 가중치를 조정해 충돌과 과부하를 줄입니다.

운영 원칙

제품 수준의 안정성과 공정성을 유지하기 위해, 플랜 구조와 기여 평가 규칙을 함께 설계합니다.

자원 사용 상한 기여 클라이언트는 CPU/GPU 사용률을 제한하고, 사용자가 다시 작업을 시작하면 자동으로 일시정지합니다.
패널티의 점진적 적용 예약 불이행이 반복될수록 효율 감소, 기여 제한, 단기 구독 제한을 순차적으로 적용합니다.
작업 재분배 노드 실패나 연결 끊김이 발생하면 작업은 다른 기기에 재배정되고, 반복 실패 작업은 격리 큐로 이동합니다.
